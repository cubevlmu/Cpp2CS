# 静态 Windows 运行库配置

`msvc-fh4-x64.json` 来自 MSVC 14.44 x64 的独立 COFF 归档。包含 FH4 分派闭包的完整节摘要、重定位关系、引用数据及 CRT 边界函数。配置不包含待分析程序的地址、方法名称或文件摘要。

配置中的 `Sources` 保存供应商归档摘要。生成器为 `native/tools/build_fh4_profile.py`，依次接受 `libvcruntime.lib`、`libcpmt.lib`、`libcmt.lib`、`libucrt.lib` 和输出路径，不读取游戏二进制。

匹配时只归零 COFF 明确列出的重定位字段；内部引用必须绑定同一节和符号偏移。系统调用绑定 IAT，安全 cookie 和 CFG 指针绑定 PE 加载配置。CRT 函数边界匹配独立函数完整体。直接调用后的可选单字节 NOP 仅在已知 CALL 指令边界消去。

两种标准异常类内联形态另有指令重排规则：复制构造保持目标清零、vptr 写入及复制参数，调用顺序不变；`what()` 在有效异常对象的同一指针成员和只读后备字符串之间选择。规则不适用于任意函数或业务类型。

配置只证明对应运行库契约。托管投影还必须核对 FH4 状态、IL2CPP 包装类型、funclet 父帧、续接及清理控制流；未知运行库或不支持的原生异常继续保留诊断。

数学根 `modf`、`powf`、`acosf`、`cosf`、`sinf`、`sqrtf` 核对 UCRT 的完整函数节、常量及重定位闭包，再按 Win64 签名投影。数学内部入口和数据引用递归核对；栈破坏检查使用独立 CRT 边界。CPU 能力变量绑定真实可写数据，保留运行时分支，不按当前机器配置折叠。`modf` 保留指针写出，其余保留单精度库入口；这些身份契约不意味着函数无副作用。

`memset` 根来自 VCRuntime，按完整函数及引用关系证明身份。Win64 参数依次为 RCX、RDX、R8，RAX 返回目标地址；定长栈帧清零复用公共内存归一，其他写入范围继续由调用契约保留。

清理控制流另使用独立 CRT 的 `free`、`_free_base`、`_invoke_watson`、`__std_terminate` 完整体核对正常返回或终止契约。该契约不提供访存纯性，也不用于删除清理调用。不返回分析只在 FH4 没有捕获区、状态及全部清理控制流已验证时越过未投影 EH 门槛；未知回调、间接转移、动态换栈和可达陷阱仍拒绝证明。

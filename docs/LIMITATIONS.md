# 已知局限

## 状态与适用边界

Win64 后端为未完成的实验实现，尚未与 ARM64 达到同等级。当前保留已有成果及诊断，不承诺完整恢复、整个源码工程可编译、语义等价、真实游戏运行或后续修复时限。

ARM64 的支持也有运行时布局、输入版本和模式识别前提。没有同一游戏、匹配版本的 ARM64 构建，就不能给出逐业务函数的跨架构成功率比较。

## L1/L2 与公共恢复之间仍有差距

两端共用大部分 L3 和输出，但 L2 入口不同。ARM64 执行完整的 45 条规则表，Win64 直接执行其中 9 条，另有 14 条显式、部分或后置替代；22 条未进入同一 L2 规则序列。

未直接启用不代表整项能力完全不存在，L3 可能覆盖部分形态；有替代路径也不代表时序和证明覆盖一致。含 ARM64 指令、固定寄存器或运行时布局的规则不能直接放开。详见 [L2 对照](L2_PARITY.md)。

## 机器指令与原子操作

- 普通整数、分支、标量浮点及部分向量操作能够提升，但不是完整 x86-64 指令集模拟。
- 未建模的 SLEIGH 用户操作继续产生 Opaque；真正恢复中的 LOCK/CMPXCHG 语义仍不完整。
- 未用输入证明中的保守 LOCK 读集合只用于依赖分析，不能代替原子读写、返回值、内存顺序或 GC 效果的恢复。
- ARM64 已有引用 CAS 运行时模式及公共 `CompareExchangeReference` 操作；Win64 仍需完整核对原子 helper 与写屏障契约后衔接。

## Windows 异常及不返回证明

- 展开记录和 FH3/FH4 元数据读取不代表任意 EH 都能恢复成托管异常结构。当前投影主要覆盖受限 FH4 形态。
- 已验证的父帧、清理、续接及终止路径才能进入分析图；动态换栈、未知回调、不支持的 funclet 或布局仍有拒绝边界。
- 不返回证明、异常图建立和托管 `throw` 身份是三件不同的事。无返回路径已成立的包装仍可能没有可写出的托管终结语句。
- 部分异常 helper 识别仍要求原始映像记录没有未建模 EH，未与已经验证的 FH4 计划完整衔接。
- 不能删除 breakpoint、仅凭 UHANDLER 标志认定不返回，或忽略真实清理来提高成功率。

## Win64 ABI 与完全共享泛型

- 固定大小标量、小结构体、间接副本、隐藏结果缓冲区、隐藏 MethodInfo 和栈位置已有部分支持。
- Win64 对大小或布局未知的完全共享值参数/返回值仍存在显式拒绝；ARM64 的动态共享值路径尚未完整移植。
- 受限 icall 包装证明不覆盖全部多片聚合、栈实参及间接返回组合。
- 不得把未知 T 猜成 8 字节，不得照搬 ARM64 的寄存器位置，也不得忽略 ABI 无法解释的输入。

## 元数据、守卫与运行时操作

- 已识别 InitMetadata 不等于调用可直接删除。槽位身份、返回实体、两臂合流、真实写入及异常效果仍需证明。
- 支配路径上的低位事实可用于归一，但不能扩展成整个寄存器的常量。
- 部分两臂不一致、嵌套初始化或操作数未恢复的路径仍失败。
- Box、类初始化、泛型元数据、接口分派和线程静态字段等存在 Win64 识别或衔接缺口。公共运行时操作已经存在，也可能因上游证据不足而无法使用。

## 调用身份、ICF 与库入口

- 同一入口可能对应多个托管声明，完整签名、初始化上下文、MethodInfo 使用和访问权限必须共同成立。
- 空 RET 入口也不能任取候选；返回寄存器保留关系和实参求值效果仍可能被观察。
- 一些原生跳板、工厂和运行时调用尚未获得完整语义契约。
- CRT 配置来自独立供应商归档的受限版本。未知版本或引用关系不匹配时不产生身份结论。
- 静态 CRT 数学入口映射到 `ucrtbase.dll` 后，线程错误状态、自定义 matherr 回调及浮点环境的跨运行时等价未做执行验证。

## 帧、副本、结构体和返回缓冲区

- 调用前临时副本、跨块地址合流、别名、重叠 ref、异常清理观察到的局部单元仍是主要限制。
- 只有真实范围和生命周期已经证明，才能提升局部内存。未知长度和捕获不能统一改成“不逃逸”。
- 部分分支或循环中的结果缓冲区仍无法证明唯一位置，部分宽寄存器和分段写入仍丢失整体结构体来源。
- 私有字段组成结构体失败，不足以证明是公共前端上限。需要先排除 Win64 没有恢复整体复制、公共构造或访问器的可能。

## 公共输出与合法性

- 同宽整数/浮点位重解释依赖目标核心库中的 BCL 契约。核心库裁剪后缺少所需方法时，当前输出缺少部分后备路径。
- 私有 API 调用、只读字段、构造顺序、依赖体及部分非标量比较仍会被合法性检查拒绝。
- 拒绝发生在共同检查中，不代表根因与 Win64 无关；可能是上游未还原合法的公开调用或整体值。
- 不通过放宽访问权限、占位实现或修改执行对照模型，把失败计成恢复成功。

## 数据含义

完整写出率、静态检查通过率、源码编译通过率与执行语义正确率必须分开。静态检查能够发现结构、类型、访问及部分合法性问题，不能证明行为与原程序相同。当前没有给出语义正确率或整游戏可运行率。

匿名全量记录及剩余问题归因见[验证记录](VALIDATION.md)。多个阻塞会落在同一函数上，诊断桶不能直接相加；修复单个桶也不保证立即新增相同数量的成功方法。

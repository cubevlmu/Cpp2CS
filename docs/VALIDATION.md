# 验证记录与统计口径

## 已有验证

现有开发验证包括托管项目与原生桥编译、原生 CFG/P-code 核对、部分独立运行库契约核对，以及完整主逻辑程序集的恢复、CIL 写出、托管静态检查和 C# 生成。

仓库保留已有的结构性与回归检查代码。它们覆盖选定的 ABI、指令、内存、调用及异常形态，不代表完整指令集或所有 Unity 版本已经通过验证。项目能编译也不代表所有检查都已执行。

## 匿名本地全量结果

同一输入、同一完整主逻辑程序集的固定范围为 **5085 个方法定义、3869 个原生入口**。依赖按输出所需处理，单列，不计入成功率分母。

| 指标 | 对照基线 | 当前保存结果 |
|---|---:|---:|
| 完整写出 | 4555 / 89.58% | **4625 / 90.95%** |
| 写出且通过托管静态检查 | 4533 / 89.14% | **4601 / 90.48%** |
| 未恢复 | 519 | 440 |
| 写出失败 | 11 | 20 |
| 已写出但静态检查失败 | 22 | 24 |
| 原有完整方法回退 | — | 0 |
| 原有成功方法 CIL 摘要变化 | — | 0 |
| 已写出原生入口 | 3341 / 3869 | 3411 / 3869 |

当前严格未通过共 **484 个**：440 个恢复洞、20 个写出失败、24 个已写出但静态检查失败。最后一组不能计入“检查通过”。写出失败增多包含此前恢复洞解除后才暴露的输出问题，不等于已有成功方法发生回退。

这些结果只描述该匿名输入，不是所有 IL2CPP 游戏的预期成功率。样本、业务名称、入口地址及逐方法原始报告不随源码发布。

## 剩余归因的证据等级

| 分类 | 方法数 | 解释 |
|---|---:|---|
| 已证有 Win64 能力缺口 | 87 | 82 个未投影异常包装调用方与 5 个共享泛型 ABI 拒绝方法；65 个原子 helper 调用方全部包含在前 82 个中 |
| 已证共同输出契约缺口，上游仍需排查 | 9 | long/64 浮点位重解释需要核心库缺失的 BCL 方法；上游能否避免位重解释未判定 |
| 混合或未闭合根因 | 388 | 不能统一认定为 ARM64 原本也不支持 |

其中 82 个缺少控制流终结语句的方法，与上述 82 个异常包装调用方完全重合。因此控制桶是相同阻塞的连带表现，不是另一个独立的 82 方法工作量。

其他诊断标签可重叠：内存类洞涉及 237 个方法，其中 89 个只报告内存类洞；ICF 身份未证明涉及 69 个，帧/ref/副本/结果缓冲区直接诊断涉及 64 个，私有字段投影涉及 55 个，结构体组成证明涉及 29 个。不能把这些数相加。

若一个函数同时含原子调用、未投影抛出和结构体问题，仅修其中一项可能完全不增加完整写出数。必须比较同一方法集合的最终状态、检查结果和已发布 CIL，而非仅比较诊断总条数。

## 未验证的内容

- 没有同一游戏、匹配版本的 ARM64 二进制对照，不能给出逐函数的跨架构成功率。
- 没有以生成程序集运行完整游戏，也没有给出全量执行语义正确率。
- C# 项目生成完成不等于整个项目已通过编译或能够放回 Unity 运行。
- 原生调用契约的静态识别不能替代跨运行时状态与异常行为的执行验证。
- 个别样本或检查通过不能推广到所有编译器、优化选项、运行时版本与异常形态。

## 后续复核方式

使用匹配二进制与元数据，固定完整程序集和定义分母；分别保留恢复状态、发布摘要、静态检查及源码诊断。对照时核对新增成功、回退和原有 CIL 变化，并检查是否只是把阻塞转移到其他阶段。

需要判断后端与管线归属时，应先核对进入公共分析前的调用签名、类型、运行时操作和内存关系是否完整。不能仅依据报错文件位于公共代码，就将问题列为共同前端限制。
